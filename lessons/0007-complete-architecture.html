Every Service Connection

Each arrow in the diagram above has a specific protocol, authorization, and lesson behind it.

User → CloudFront
HTTPS 443 · TLS 1.2+ · ACM cert (us-east-1) · WAF filters before origin
CloudFront → S3
HTTPS · OAC-signed requests · bucket policy allows only this distribution's ARN
CloudFront → ALB
HTTPS on /api/* path · ALB security group allows inbound 443 from CloudFront IP ranges
ALB → ECS Tasks
HTTP 8080 · ECS security group allows inbound 8080 from ALB security group ID only
ECS → RDS Proxy
PostgreSQL 5432 · TLS (sslmode=require) · RDS SG allows 5432 from ECS SG only
ECS → ElastiCache
Redis 6379 · ElastiCache SG allows 6379 from ECS SG only · both in private subnets
ECS → S3
HTTPS · via VPC Gateway Endpoint (no NAT) · IAM Task Role s3:GetObject / s3:PutObject on specific bucket ARN
ECS → Secrets Manager
HTTPS · via VPC Interface Endpoint (no NAT) · IAM Task Role secretsmanager:GetSecretValue on specific secret ARN
ECS → ECR
HTTPS · via NAT Gateway (ECR Interface Endpoint optional) · Execution Role ecr:GetDownloadUrlForLayer
ECS → CloudWatch
awslogs driver sends stdout/stderr · Execution Role logs:CreateLogStream, logs:PutLogEvents
RDS → S3
Automated backups and snapshots stored in AWS-managed S3 (transparent, no config needed)

Provisioning Order

AWS resources depend on each other. Provision in this sequence — each phase can proceed in parallel within itself, but must complete before the next phase starts.

Phase 1 Foundation — no dependencies ~5 min
VPC + subnets + route tables (everything lives here)
Internet Gateway + NAT Gateway
Security Groups (all four: ALB, ECS, RDS, Redis)
IAM roles (Task Role + Execution Role)
ACM certificate request in us-east-1 (DNS validation — start early)
ECR repository
Phase 2 Data + secrets — needs VPC + IAM ~15 min (RDS takes longest)
KMS key for RDS encryption
DB Subnet Group (needs subnets)
RDS PostgreSQL Multi-AZ (needs subnet group, KMS, SG)
ElastiCache Redis (needs subnets, SG)
Secrets Manager secrets (needs RDS endpoint to build URL)
VPC Endpoints for S3 + Secrets Manager
Phase 3 Compute — needs everything above ~5 min
Build + push Docker image to ECR
ECS Cluster
ECS Task Definition (needs ECR image, IAM roles, secrets ARNs)
ALB + Target Group + Listener
ECS Service (needs task def, ALB target group, subnets, SG)
RDS Proxy (needs RDS instance, IAM role)
Phase 4 Frontend + DNS — needs ACM cert to be validated ~10 min (CloudFront deploys slowly)
S3 bucket (private, block public access)
Build SPA + sync to S3
CloudFront distribution (needs S3, ACM cert, ALB)
OAC + S3 bucket policy
Custom error responses (SPA routing fix)
Route 53 Alias records (needs CloudFront domain)
Phase 5 Operations — add after first successful deploy ongoing
CloudWatch alarms (CPU, memory, DB connections, 5xx errors)
AWS WAF rules on CloudFront (OWASP managed rule group)
ECS auto-scaling policy
CloudWatch dashboard
SNS topic → email/PagerDuty for alarm notifications
RDS Performance Insights enabled
Use Infrastructure as Code from day one Do not click through the AWS console to build this. Use Terraform (most widely used, large ecosystem) or AWS CDK (TypeScript/Python code that generates CloudFormation). Console-built infrastructure cannot be reproduced, reviewed in PRs, or safely destroyed and rebuilt. The provisioning order above is also your Terraform module dependency order.

Decisions Still to Make

These are not covered in the six lessons but must be decided before production.

DecisionOptionsRecommendation
Infrastructure as Code Terraform · AWS CDK · CloudFormation · Pulumi Terraform — largest community, provider ecosystem, readable HCL
User authentication Amazon Cognito · Auth0 · custom JWT Cognito for AWS-native (free tier, MFA, social login). Auth0 if you need advanced customization.
CI/CD pipeline GitHub Actions · AWS CodePipeline · GitLab CI GitHub Actions — widest adoption, good AWS integrations via OIDC (no stored access keys)
Async job processing SQS + Lambda · SQS + ECS task · EventBridge SQS + Lambda for lightweight jobs (email alerts, notifications). SQS + ECS task for heavy processing (trade reconciliation, report generation).
Observability CloudWatch only · Datadog · Grafana + Prometheus Start with CloudWatch (zero setup). Add Datadog or Grafana when you need cross-service dashboards or better alerting UX.
Database engine RDS PostgreSQL · Aurora PostgreSQL · Aurora Serverless v2 RDS PostgreSQL to start (simpler, cheaper). Migrate to Aurora if you need read replicas, faster failover (<30s), or serverless scaling for unpredictable load.
Secrets rotation Manual rotation · Secrets Manager auto-rotation Enable Secrets Manager auto-rotation for the RDS password — it rotates the credential and updates the secret automatically on a schedule.
Multi-region Single region · Active-passive · Active-active Single region (us-east-1) to start. Add a passive DR region only when uptime SLA demands it — multi-region complexity is significant.
